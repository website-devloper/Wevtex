# WEVTEX — Design Elevation Skill

You are doing a **design-only** pass on an existing, working Next.js + Tailwind
site. Do not rewrite content, change data files, or alter business logic. Every
change below is visual: layout, spacing, color value, borders, type scale, and
restrained hover. Work through it in one session, section by section, committing
as you go.

The brand is fixed: white canvas, ink `#101112`, signal lime `#C6F24E`, Onest for
type, mono for labels. That does not change. What changes is how the page uses
**value, structure, and rhythm** so it reads as authored by a designer, not
generated by a template.

## The core principle (read first)

An AI-generated layout looks generated because it does ONE thing everywhere: the
same near-white background, the same rounded-corner faint-border card, the same
even spacing, repeated down the page. A human designer instead makes each section
**decide what it is** — heavy or airy, dark or light, dense or spacious. Your job
is to replace uniformity with deliberate, sectional decisions.

Three rules govern the whole pass:

1. **Compose with value.** Roughly 30% of the page becomes true ink `#101112` with
   light text. Sections alternate so the eye never travels through more than ~2
   light sections without hitting a dark anchor. This single change removes most
   of the generated feel.
2. **Vary structure by content.** No two adjacent sections should share the same
   container pattern. A grid with dividers, then editorial rows, then full-bleed
   image tiles, then a dark stat band — not eight identical card grids.
3. **Fix contrast honestly.** Body text goes to `#3A3A38` or darker (never the
   faint grey it is now). Borders become visibly present (`#DADAD6`) OR are
   replaced by fill + a real soft shadow. Text should never make the reader work.

## Reusable-component strategy (important)

Elevating each section does NOT mean bespoke one-off code everywhere. Build a
**small set of primitives**, then vary them with props — that is how you get
distinct sections AND reuse:

- `<Section tone="light|paper|ink" spacing="tight|normal|loose">` — wraps every
  section, owns background value + vertical rhythm. The tone prop is how you get
  the light/dark composition without duplicating markup.
- `<Eyebrow>` — the mono uppercase label with the small lime tick. One component,
  used everywhere.
- `<SectionHeading>` — Onest heading with the lime-marker or mixed-weight emphasis
  on one word (accept a prop to choose which device, so headings aren't all
  emphasized identically).
- `<Surface variant="bordered|filled|ghost">` — the card primitive. `bordered`
  for grids, `filled` (bg + shadow, no border) for testimonials, `ghost` (no
  container) where a section should breathe. Same component, three faces.
- `<Marker>` — the lime highlight behind a word. `<HandUnderline>` — an
  alternative hand-drawn-style SVG underline, used sparingly so emphasis varies.

Distinct sections come from *composing these differently*, not from rewriting
them. Keep them in one place so the whole pass is consistent and fast.

## Restraint on motion (the user asked for this explicitly)

Hover should be felt, not performed. ONE idea per element, 150–220ms, ease-out.
Allowed vocabulary — pick per section, never stack more than one:

- link/nav: lime underline wipes in left→right.
- card: border → ink or lime, OR a `-3px` lift with a soft shadow. Not both.
- button: fill deepens slightly + `-2px`. That's all.
- project row: the browser-frame image nudges up a few px to reveal more.
- image tile: a slow `1.03` scale under a fixed-height mask (250ms).

No parallax, no bouncy springs, no glow, no multi-property animations, no
scroll-jacking. Respect `prefers-reduced-motion` everywhere. If a hover needs a
sentence to explain, it's too much.

## The "human, not generated" details

Add a FEW deliberate imperfections — this is what signals a person chose things:

- A faint film-grain/noise overlay on the ink sections only (very subtle, ~3%
  opacity). Warms the black, kills the flat-digital feel.
- One off-grid moment per page: a heading that breaks the left margin, or an image
  that bleeds off one edge. Not everywhere — once.
- Vary the emphasis device: some headings use the lime marker, some use
  mixed-weight (grey line, one bold-ink word), one or two use the hand underline.
  Never the same device on every heading.
- Expressive spacing: tight between related blocks, generous before a new idea.
  Uniform padding is the generated tell.

## Section-by-section direction

Each note says: what it should BECOME, its tone, its structure, its one hover.
Copy is rewritten separately — do not touch it here.

### Header / mega-menu
Already strong. Leave structure. Only: on scroll past the hero, condense to a
slim solid-white bar with a hairline bottom shadow (200ms). Nav links get the
lime underline-wipe on hover. Nothing else.

### Hero — give it its own stage
The hero must stop sharing the same off-white as the section under it. Make it a
distinct ground: either **ink `#101112` with the product render glowing against
it and the lime marker on "clients,"** or a warm off-white panel with a hairline
frame the render can bleed out of. Keep the Google 5.0 / reviews chip — but move
it to sit with the CTA so proof and action are together. Hover: buttons only.
Tone `ink` (recommended) · structure: two-column, render allowed to bleed off the
right edge (the one off-grid moment). Spacing `loose`.

### "La plupart des sites… aucun client" — the tension beat
This is your emotional hook; make it a full dark section already (it half is).
Ink background, large centered statement, the negative word in the lime marker.
Keep it SPARSE — this section's power is emptiness and contrast. No cards. Tone
`ink` · structure `ghost` · spacing `loose`.

### Services (the 8) — a precise grid, not floating cards
Drop the floating faint-bordered cards. Make it a **bordered grid with visible
dividers** (a 4×2 matrix with hairline `#DADAD6` rules between cells, no gaps),
so it reads as one engineered system, not eight loose tiles. Enlarge the icons
and give them a lime tint; darken the corner arrow. Hover: the whole cell's
background lifts to `#F5F5F2` and its arrow slides right 4px. Tone `light` ·
structure: divider grid · spacing `normal`.

### Projects — editorial, and dark
Flip this section to ink. The featured row (browser frame + details, lime metric)
looks premium on dark. The index list below gets stronger dividers and mono
numbering in lime. Add the small "Résultats illustratifs" caption once. Hover:
featured image nudges up; index row name gets the lime marker. Tone `ink` ·
structure: one editorial row + index list · spacing `normal`.

### Stats — dark band, and FIX THE ZEROS
Currently renders 0 / 0 / 0 / 0% live — the count-up never receives its targets.
Fix the values and trigger on scroll with a static fallback to the final number.
Put the band on ink, numbers in large Onest white, the unit/label in lime.
No cards — just four big numbers with generous space. Tone `ink` · structure
`ghost` · spacing `normal`.

### Testimonials — filled surfaces, real weight
Switch from faint-bordered cards to `filled` surfaces (subtle `#F5F5F2` bg + soft
shadow, no border). Pull the "5.0 · 94 avis Google" proof up here so it's near the
quotes. Emphasis word (e.g. "doublé") stays in the marker. Hover: `-3px` lift
only. Tone `paper` · structure: filled cards · spacing `normal`.

### Sectors — full-bleed image tiles
These want to be visual, not carded. Full-bleed image tiles with a dark
bottom-to-top gradient overlay so the white label is always legible (it's
borderline now). Equalize image heights with a fixed mask. Hover: slow `1.03`
image scale under the mask, label holds still. Tone `light` · structure: image
tile grid · spacing `normal`.

### Pricing — already your best; refine only
Keep the dark section and the lifted "Le plus demandé" card. Only refinements:
tighten the numeric alignment (prices on a baseline), make the non-featured tiers
slightly recede so the popular one wins the eye, keep hover to the button.
Tone `ink` · structure: pricing cards · spacing `loose`.

### FAQ + WhatsApp card
Structurally fine. Give the accordion a calm open/close (max-height + opacity,
200ms), a lime `+`→`×` on the active row. The black WhatsApp card stays as the
anchor. Tone `paper` · structure: accordion + feature card · spacing `normal`.

### Footer
Strong. No structural change. Optional: the faint grain on its ink so it matches
the other dark sections.

## Sector & Services sub-pages
The Sector page is the weakest (too much pale empty space, tiny faint icons). Give
it the Services page's density and borrow the dark technology band. Same
primitives, same tones — a sector page should feel as substantial as the services
page, never like a thin stub.

## Definition of done
- ~30% of page height is ink-toned; no run of >2 light sections without a dark anchor.
- Body text ≥ `#3A3A38`; no hairline-invisible borders remain.
- No two adjacent sections share the same container pattern.
- Every interactive element has exactly one restrained hover; reduced-motion honored.
- Stats show real numbers, not zeros.
- All new visuals composed from the shared primitives — no duplicated one-off section shells.
- No copy, data, or logic changed in this pass.




## Dark section backgrounds — build these deliberately

Both ink sections must NOT be a flat #101112 fill (that reads as generated).
Add one quiet layer of depth to each. Build a reusable <InkBackdrop variant>
so both share the same grain and base.

<InkBackdrop> base (both variants):
- background: #101112
- a film-grain / noise overlay at ~3-4% opacity across the whole section
  (a tiny tiled PNG or an SVG feTurbulence). This is the key human detail.
- respects prefers-reduced-motion (no animation on it — it's static).

variant="spotlight"  → for "La plupart des sites… aucun client":
- add a soft radial gradient centered behind the text: from #1A1D22 at center
  fading to transparent by ~60% radius. The headline sits in a pool of light.
- keep the section SPARSE — no cards, no dividers. Emptiness is the point.
- optional: one oversized faint mark (the W or a » chevron) at ~5% opacity,
  bleeding off one edge. Barely visible.

variant="data" → for the stats band:
- no glow. Instead, thin vertical hairline dividers (#2A2D33) between the four
  stats, so it reads as one engineered strip.
- numbers: large Onest, white. Labels/units under them: lime (#C6F24E).
- FIX THE ZEROS: real values, count-up on scroll with a static fallback.

Both: text is off-white #F4F5F2, never pure white. Lime stays the single accent.
